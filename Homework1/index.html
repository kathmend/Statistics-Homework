Private Key to Public Key

A simple experiment with elliptic-curve scalar multiplication and some statistical observations.

1. INTRODUCTION

From private to public

A private scalar k is multiplied by a public base point G. The result Q = kG is the public point. Here multiplication means repeated elliptic-curve point addition, not ordinary multiplication of coordinates.

This is an educational example using a simplified elliptic curve. Ethereum uses the much larger secp256k1 curve.

3. POINT ADDITION

Why point addition works

Adding different points

For P = (x₁, y₁) and R = (x₂, y₂):

λ = (y₂ − y₁) · (x₂ − x₁)⁻¹ mod 17
x₃ = λ² − x₁ − x₂ mod 17
y₃ = λ(x₁ − x₃) − y₁ mod 17

Doubling a point

When adding a point to itself:

λ = 3x₁² · (2y₁)⁻¹ mod 17
x₃ = λ² − 2x₁ mod 17
y₃ = λ(x₁ − x₃) − y₁ mod 17
Worked example — 2G: G = (1, 5). The modular inverse of 10 is 12. So λ = 3 · 12 mod 17 = 2. Then x = 2² − 1 − 1 = 2 and y = 2(1 − 2) − 5 ≡ 10. Therefore 2G = (2, 10). The exponent −1 means modular inverse, not division over real numbers.

The point at infinity O acts like zero: P + O = P. For this base point, 9G = O, so the finite non-identity public points come from k = 1, …, 8. All results repeat after 9 steps.

5. DISCUSSION

What do these results mean?

01

Distribution and apparent uniformity

Uniformly choosing k among 1–8 gives eight equally likely public points because each scalar maps to a different point. The coordinates are not uniformly distributed across F₁₇: some x-values repeat and many field values never appear.

02

Bit balance and correlation

Some coordinate bits occur more often than others. Correlation can be small even when a mapping is completely predictable. Neither result proves cryptographic security.

03

One-way function versus hash

Scalar multiplication is deterministic and efficient in the forward direction. Its real-world one-way security relies on the Elliptic Curve Discrete Logarithm Problem (ECDLP): recovering k from G and Q should be computationally infeasible. Hash functions instead accept arbitrary-length inputs and produce fixed-length digests; avalanche behavior is a common desirable hash property, not the basis of ECC security.

04

From this toy curve to Ethereum

Our subgroup has only nine points, so anyone can recover k by testing a few candidates. Ethereum uses secp256k1 with vastly larger parameters. This program illustrates the mathematical idea; it does not generate real Ethereum keys, addresses, signatures, or secure random secrets.

Conclusion

This experiment shows how repeated point addition turns a private scalar into a public point. The statistics describe the structure of a small subgroup, but cannot establish one-way security. In real elliptic-curve cryptography, carefully selected parameters and the hardness of ECDLP are essential.
